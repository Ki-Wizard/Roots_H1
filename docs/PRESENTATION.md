# PhiloType 중간 발표 흐름

## 1. 문제 정의

기존 성격 검사는 “당신은 어떤 유형이다”라는 결과에 집중합니다. 하지만 같은 선택을
하더라도 사람마다 이유는 다릅니다. PhiloType은 선택 결과보다 선택의 기준을
보여줍니다.

## 2. 한 줄 소개

딜레마 선택과 답변 이유를 바탕으로 사용자의 철학적 사고방식과 가치 판단 기준을
분석하는 서비스입니다.

## 3. 핵심 차별점

- A/B 딜레마 선택과 한 줄 이유를 함께 분석
- 단순 철학자 매칭이 아닌 4개 사고축 프로필 제공
- 결과에 실제 답변 근거를 표시
- 나와 반대되는 관점과 사고 훈련 처방전 제공
- 공유 가능한 결과 카드

## 4. 사용자 흐름

1. 사용자가 딜레마 질문에 답합니다.
2. 각 선택의 이유를 한 문장으로 작성합니다.
3. 코드가 사고축 점수를 계산합니다.
4. 대표·보조 철학 유형과 철학자를 매칭합니다.
5. 리포트 생성기가 선택 이유를 설명과 근거로 변환합니다.
6. 결과 카드, 반대 관점, 사고 훈련, 공유 문구를 보여줍니다.

## 5. 기술적 판단

AI가 점수와 유형까지 결정하면 같은 답변에도 결과가 흔들릴 수 있습니다. 그래서
분류는 코드가 담당하고 AI는 해석 문장만 담당하도록 역할을 나눴습니다.

기본값은 비용이 발생하지 않는 Mock 모드이지만, 로컬 `.env`에서
`AI_MODE=openrouter`와 `OPENROUTER_API_KEY`를 설정하면 OpenRouter를 통해 실제 AI
리포트 문장을 생성합니다. Mock과 실제 AI는 같은 응답 스키마를 사용하므로 프론트는
동일한 결과 화면을 렌더링합니다.

## 6. 현재 진행 결과

### 백엔드

- 스토리형 질문 40개 실제 동작
- 4개 사고축 가중치·정규화 계산
- 대표·보조 철학 유형 및 철학자 매칭
- 입력 누락·선택지 검증
- Mock 리포트와 OpenRouter 리포트 생성기 구현
- 실제 AI 응답을 동일 `GeneratedReport` JSON 구조로 파싱
- 동일 입력에 대한 Mock 결정성 테스트와 OpenRouter 파싱 테스트

### 프론트엔드

- 시작, 설문, 로딩, 결과 화면
- 모바일 반응형 UI
- A/B 선택과 한 줄 이유 입력
- 사고축 그래프, 답변 근거, 처방전, 공유 문구

## 7. 시연 순서

1. `GET /api/health`에서 현재 시연 모드가 `aiMode: openrouter`,
   `persistence: false`인지 확인합니다.
2. 웹에서 딜레마 질문 40개에 답하고 이유를 작성합니다.
3. 결과 상단에서 `openrouter` 모드로 실제 AI 리포트가 생성됐는지 확인합니다.
4. 분석 결과의 대표 유형과 4개 사고축을 확인합니다.
5. 답변에서 생성된 근거와 사고 훈련 처방전을 보여줍니다.
6. 점수·유형은 코드가 고정하고 AI는 문장 생성만 담당한다는 점을 설명합니다.
